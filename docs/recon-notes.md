## Sample record shapes

xref page record (`https://mystmd.org/guide/myst.xref.json`):

```json
{"kind": "page", "data": "/index.json", "url": "/"}
```

xref heading record (`https://jupyterbook.org/myst.xref.json`):

```json
{
  "identifier": "new-to-jupyter-book",
  "kind": "heading",
  "data": "/index.json",
  "url": "/",
  "implicit": true
}
```

Heading records carry an extra `implicit` field not called out in the design spec's assumed minimal field set (`kind`, `url`, `data`).


## `data` field validity

`data` was present on **every** page record on all 4 reachable sites (0 missing, out of 90 + 24 + 12 + 9 = 135 page records checked).


## URL → `data` derivation rule (slashes → dots)

Verified on `https://jupyterbook.org`'s nested pages:

| url | data | rule-derived (`url` minus leading `/`, `/`→`.`, `+ .json`) | matches? |
|---|---|---|---|
| `/community/team` | `/community.team.json` | `community.team.json` | yes |
| `/community/jobs` | `/community.jobs.index.json` | `community.jobs.json` | **no** — folder-index page gets an extra `.index` segment |
| `/community/jobs/2026-03-community-mgr` | `/community.jobs.2026-03-community-mgr.json` | `community.jobs.2026-03-community-mgr.json` | yes |

**Conclusion:** the slash→dot rule holds for ordinary pages but not for a folder's index page, which is suffixed `.index.json` rather than `.json`.
This confirms the plan's resolution rule: always use the xref `data` field as the source of truth; treat URL-derivation as a fallback only, and expect it to be wrong for index pages.

## `myst.search.json` shape

Found on `https://jupyterbook.org` only (152 records).

Top-level keys: `version`, `records`.

`record[0]` (a heading-level entry):

```json
{"hierarchy": {"lvl1": "Accessibility"}, "type": "lvl1", "url": "/accessibility", "position": 0}
```

A content-type entry (`record[5]`) additionally carries `content` (excerpted page text) and a `url` with a `#fragment`:

```json
{
  "hierarchy": {"lvl1": "Accessibility", "lvl2": "Get involved"},
  "content": "Technical details » ...",
  "type": "content",
  "url": "/accessibility#get-involved",
  "position": 5
}
```

This looks like an Algolia DocSearch-style record set (`hierarchy`/`type`/`url`/`position`/`content`), richer than the design spec assumed (a bare `records` array of page/heading pointers).


## Anything else contradicting assumptions

See `docs/decisions.md` for the one-line log.
Summary:
- `data` field derivation via slash→dot breaks for folder-index pages (`.index.json` suffix).
- Heading xref records carry an undocumented `implicit` field.
- `myst.search.json` record shape is richer (DocSearch-like, with `content` and `position`) than assumed.
- `next.jupyterbook.org` was unreachable during this recon session (network/DNS timeout), not a script issue.
- The bare `mystmd.org` domain has no `myst.xref.json` — subpath deployments only.
